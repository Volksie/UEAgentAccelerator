# C++ symbols used from Blueprint graphs

Generated by the AgentMemoryDump commandlet. Do not hand edit.

**This is the blast radius index.** Every row is a use of a C++ function or property from
inside a Blueprint graph, resolved through the node's member reference rather than matched
by name. No C++ tool can produce these: clangd cannot see .uasset files, ripgrep skips them
silently, and renaming a symbol listed here still compiles.

**Covers:** function calls (`call`), property reads (`read`) and property writes (`write`)
from every event graph, function graph and macro graph of every Blueprint under /Game and
the project's plugins, plus `bind`: a C++ `BindWidget` or `BindWidgetAnim` property bound by
name to a widget or animation in a Widget Blueprint's designer tree, which the widget compiler
enforces and no graph node records. Stated explicitly because an index with no rows of a
given kind is otherwise indistinguishable from an index that does not cover that kind, and a
reader who assumes the latter will go and grep binaries.

**Does not cover:** component templates and variable or pin *types* that name a C++ class,
default values, and anything outside a Blueprint asset (materials, Niagara, data tables).
Those are uses of a class, not of a member, and `blueprints/<Parent>.md` is where a class's
Blueprint children and component counts live.

**Walk coverage:** 3 Blueprints, 1 data-only, 3 walked, 2 with edges.
Data-only Blueprints have no graphs by construction and cannot produce an edge; they are not
a gap in the walk. Every Blueprint that could be loaded was walked, so within what this file
covers, absence is exact.

A symbol absent from this table has no Blueprint users of the kinds covered above. That is a
real answer to the negation form of the question, not an absence of evidence, and it is just
as useful as a hit.

**This file is an index.** One row per owning C++ class, with its uses in
`bpcallers/<Class>.md`. Grep this table for the class you are about to change and read
that one file. A class absent from this table has no Blueprint users at all.

**Rows are classes, not members.** Grepping here for a function or property name finds
nothing even when that member has Blueprint users. Go by the owning class, or straight to
`bpcallers/<Class>.md`, which lists every member of that class with its users.
